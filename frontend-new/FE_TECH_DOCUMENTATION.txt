### 1.1 React 19 in Practice: Building Modern, Performant, and Scalable Frontend Applications
*Author: Ted E Nelson (December 2025)*
- **Objective**: Transitioning from Client-Side Rendering (CSR) to a "Full-Stack Frontend" approach using React Server Components (RSC).
- **Key Concepts**:
  - **React Compiler**: Automatic optimization of JavaScript to eliminate manual memoization (useMemo/useCallback).
  - **Server Actions**: Handling data mutations and form submissions directly within components, reducing API boilerplate.
  - **Streaming & Suspense**: Building "Zero Latency" interfaces through progressive HTML streaming.
  - **Optimistic UI**: Using `useOptimistic` for instant screen updates.

## 2. ARCHITECTURAL PILLARS FOR PROCESS MINER

### 2.1 Full-Stack Frontend (The React 19 Approach)
Our application leverages the shift towards server-side capabilities:
- **Server Actions**: We use async functions for data mutations to simplify the data flow.
- **Enhanced Hooks**: Utilizing `useActionState` and `useFormStatus` to handle asynchronous logic and loading states natively.
- **Resource Reading**: Using the `use` API to read promises and context during render.

### 2.2 Modular Scalability (Micro-Frontends & DDD)
- **Feature-First Structure**: (Refer to `src/features/`)
  - Each domain (e.g., `explorer`, `upload`, `conformance`) is treated as an independent module.
  - Logic is encapsulated locally to prevent "dependency spaghetti."
- **Independent Deployments**: Preparing for an architecture where independent teams can deploy feature updates without affecting the entire shell.

### 2.3 Performance Optimization
- **The Compiler**: We rely on the React 19 compiler for performance; manual memoization is discouraged unless profiling shows a specific bottle-neck.
- **Optimistic Updates**: Every user interaction (mutations) should implement optimistic UI patterns to ensure the interface feels "Zero Latency."
- **Asset Loading**: Using `preload` and `preinit` APIs to minimize flickering and improve user experience during initial load.

## 3. DEVELOPMENT BEST PRACTICES

### 3.1 Type Safety & Validation
- **TypeScript**: Strict mode is mandatory. Interfaces must define clear contracts between components.
- **Zod**: All external data (API responses) must be validated at the boundary using Zod schemas.

### 3.2 State Management Strategy
- **Server State**: Managed exclusively by **TanStack Query**. Handle caching, staleness, and optimistic updates here.
- **Global UI State**: Managed by **Zustand**. Keep it minimal (e.g., auth session, sidebar state, global notifications).
- **Component State**: Use standard `useState` and `useActionState` for local interactivity.

### 3.3 Testing Strategy
- **Vitest**: Preferred test runner for unit and integration tests.
- **React Testing Library**: Focus on testing accessibility and user behavior rather than internal state/props.

## 4. FUTURE-PROOFING & AI READINESS (XOps)
As we move towards AI-ready SaaS features:
- **Observability**: Implement deep logging for every Server Action and user flow to enable diagnostic-driven development.
- **Scalability**: Core infrastructure components are designed to auto-scale, supporting the increased demand of AI-driven analytical features.
- **Agility**: The decentralized architecture allows for rapid iteration on specific AI modules without broad system impacts.
