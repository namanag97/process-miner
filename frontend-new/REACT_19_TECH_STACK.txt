REACT 19 IN PRACTICE: BUILDING MODERN, PERFORMANT, AND SCALABLE FRONTEND APPLICATIONS
========================================================================================

## 1. Executive Summary & Philosophy
This document outlines the frontend technology strategy for our "Process Miner" application, directly inspired by the principles in "React 19 in Practice" by Ted E. Nelson (2025).

Our core philosophy focuses on:
- **Performance**: Leveraging React 19's optimizing Compiler and "Zero Latency" interfaces via Optimistic UI.
- **Scalability**: Utilizing a Feature-First architecture and Nx monorepo tooling to manage complexity as the codebase grows.
- **Modernity**: Adopting the latest React 19 paradigms—Server Capabilities (where applicable), Actions, and enhanced Hooks—to future-proof our stack.

## 2. Core Technology Stack

### The Foundation
- **Framework/Library**: React 19.x
- **Language**: TypeScript 5.9+ (Strict Mode enabled for robust type safety)
- **Build System**: Vite 6.x (via @nx/vite) for lightning-fast HMR and optimized production builds.
- **Monorepo Manager**: Nx (handling dependency graph, caching, and task orchestration).

### Key Libraries
- **UI System**: Ant Design (v5.x) – Enterprise-grade component library.
- **Data Fetching/Server State**: TanStack Query (v5.x) – Managing asynchronous data, caching, and synchronization.
- **Routing**: React Router DOM (v6/7) – Client-side routing.
- **Visualization**: React Flow (node-based graphs) and D3 (custom visualizations).
- **Validation**: Zod – Schema validation for API responses and forms.

## 3. React 19 Architectural Patterns

### 3.1. The "Zero Latency" UI
We aim for immediate user feedback. Network latency should not block user interaction.
- **useOptimistic**: Implement this hook for all mutations (e.g., updating a KPI, renaming a process). The UI should reflect the change *instantly* while the server request processes in the background.
- **useTransition**: Wrap non-urgent state updates (like filtering large lists) in `startTransition` to keep the UI responsive during heavy computations.

### 3.2. Data Management & Actions
- **Actions**: Move away from manual `useEffect` handling for form submissions. Use React 19 Actions (async functions passed to `action` props) to handle form submissions automatically.
- **TanStack Query**: Continue to use `useQuery` for fetching. For mutations, integrate `useMutation` closely with React 19's optimistic updates to ensure cache consistency.

### 3.3. React Compiler
- **Automatic Optimization**: Rely on the React Compiler (available in React 19) to handle memoization (`useMemo`, `useCallback`) automatically.
- **Code Style**: Write "naive" but clean code. Do not prematurely optimize with `useMemo` unless profiling indicates a specific need. Trust the compiler.

## 4. Scalable Folder Structure (Feature-First)
To support a growing SaaS platform, we eschew "type-based" grouping (keeping all components in one folder, all hooks in another) in favor of "feature-based" grouping.

```
src/
  features/
    process-explorer/      # Feature: Process Explorer
      components/          # Components specific to this feature
      hooks/               # Hooks specific to this feature
      api/                 # API definitions for this feature
      types.ts             # Feature-specific types
      index.ts             # Public API of this feature
    user-management/       # Feature: User Management
      ...
  components/              # Shared/Generic UI components (Buttons, Layouts)
  lib/                     # Shared utilities (axios setup, date formatting)
  hooks/                   # Shared global hooks
```

**Rule**: A feature should look like a self-contained mini-application. Cross-feature imports should be minimized and ideally go through the feature's `index.ts`.

## 5. Performance & Observability

### 5.1. Render Performance
- **Suspense**: Use `<Suspense>` boundaries liberally to handle loading states declaratively.
- **Lazy Loading**: Use `React.lazy` (or standard dynamic imports) for heavy routes or feature modules to keep the initial bundle size low.

### 5.2. Metrics
- **Web Vitals**: Monitor LCP (Largest Contentful Paint) and INP (Interaction to Next Paint). React 19's concurrent features directly improve INP.

## 6. Migration & Future-Proofing
While we currently use a client-side Vite setup, we prepare for a potential "Full-Stack Frontend" future (RSC):
- **Server/Client Separation**: Mentally separate components that *only* display data (candidates for future Server Components) from those that require interactivity (Client Components).
- **Async Pattern**: Adopt the `use` API for reading promises, aligning with the pattern used in Server Components.

## 7. Development Guidelines
- **Type Safety**: No `any`. Use `zod` to validate all incoming API data at the boundary.
- **Testing**:
  - Unit: Jest/Vitest for logic.
  - Component: Testing Library for interaction.
  - E2E: Playwright/Cypress for critical flows.
- **Linting**: Strict ESLint rules (via Nx) to enforce best practices and prevent "useEffect chaos".
